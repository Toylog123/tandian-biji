# 接后端：让两个人共用一份数据

默认状态下这个应用是**单机**的，数据存在各自浏览器的 localStorage 里。
按本文配完之后，你们俩在各自手机上会看到同一份数据。

需要的东西：**一个免费的 Supabase 项目**。没有别的，也不需要服务器。

---

## 一、建项目（约 2 分钟）

1. 打开 <https://supabase.com> → 注册 / 登录
2. 点 **New project**
3. 随便起个名，比如 `lulu-menu`
   数据库密码**随便设一个**（这条路上根本用不到它，留着就行）
4. Region 选离你近的（国内的话选 Singapore / Tokyo）
5. 等 1~2 分钟建好

建好后页面上会给你两个要用的东西：

```
Project URL        https://abcdefghijklm.supabase.co
anon public key    sb_publishable_xxxxxxxxxxxxxxxxxxxxxxxx
```

---

## 二、建一张表

在 Supabase 控制台点左边的 **SQL Editor** → **New query**，把下面整段贴进去 → Run。

```sql
-- 就存一整份 JSON，不拆成多张表：两个人几十条记录，拆表纯属自找麻烦
create table if not exists lulu_menu (
  id          text primary key,
  data        jsonb      not null default '{}'::jsonb,
  updated_at  timestamptz not null default now()
);

-- 必须开 RLS，否则 anon key 等于裸奔
alter table lulu_menu enable row level security;

drop policy if exists "family read"   on lulu_menu;
drop policy if exists "family insert" on lulu_menu;
drop policy if exists "family update" on lulu_menu;

-- 家庭自用：拿到链接的人就能读写
create policy "family read"   on lulu_menu for select using (true);
create policy "family insert" on lulu_menu for insert with check (true);
create policy "family update" on lulu_menu for update using (true) with check (true);
```

跑完没报错就成功了。

---

## 三、填配置

编辑 `js/config.js`：

```js
export const SUPABASE = {
  url: 'https://abcdefghijklm.supabase.co',
  key: 'sb_publishable_xxxxxxxxxxxxxxxxxxxxxxxx',
};
```

刷新页面。管理页标题那里会出现一个小圆点：

| 显示 | 意思 |
|---|---|
| `● 仅本机` | 没配后端，数据只在这台设备上 |
| `● 同步中…` | 正在往云端写 |
| `● 已同步` | 云端和本地一致 |
| `● 云端没连上，先存本地` | 网络或配置有问题，操作没丢，只是不上云 |

---

## 四、⚠️ 安全上要知道的

这套策略是**「拿到链接的人都能改」**。也就是说：

- 你们俩的手机上完全够用，谁也不会去动它
- 但**如果有人猜到/拿到你的项目地址和 key，就能改你们的数据**
- 地址本身是保密的（只有你和拿到这个网页的人知道），但它会随网页一起分发
  ——所以**网页链接本身也要当敏感信息对待，别发到公开的地方**

想收紧到「只有登录的人能改」，得上 Supabase Auth（邮箱密码 / 魔法链接登录）。
那是另一套活，family 场景没必要，先不做。

**绝对不要把 `service_role` key 填进 `config.js`。**
那个是数据库管理员权限，填进前端等于把整个数据库交出去。
`config.js` 里只放 `sb_publishable_` / `anon` 开头的那种。

---

## 五、几个实现上的取舍

**存一整份 JSON，不拆表**
读写就是一次 GET / PUT，不用维护 schema，也不用担心迁移。
真要做「统计点过多少次」之类的分析，以后再拆表。

**图片也塞在这份 JSON 里**
图是压到 400px 的 dataURL，一张 30~45KB。几十张也就一两 MB，
jsonb 存得下。接对象存储能再小一个量级，但不是现在必须解决的。

**后写覆盖，不做冲突合并**
两个人同时改不同东西时，后写的会把先写的盖掉。
家庭场景下同时编辑的概率很低，先不管。

**写入是防抖的**
打字时每敲一下都会触发保存，但不会每敲一下都发一次请求——
停手 900ms 才推一次。页面被切到后台时会立刻推一次，避免丢最后的改动。

---

## 不想用后端？

把 `js/config.js` 里的两行留空就行。
应用会退回纯单机版，功能一模一样，只是数据各存各的。
