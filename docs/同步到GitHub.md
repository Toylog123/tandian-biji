# 怎么把 GitHub 仓库接成两台手机共用的存储

让「探店笔记」的两台手机看到同一份数据。
不用服务器、不用域名、不用数据库、不用构建——GitHub 仓库本身就是那份存储。

线上已经配好了，**你现在要做的只是在自己手机上粘一次 token**。
这份文档主要写清楚「为什么这么设计」和「以后换设备怎么办」。

---

## 三个前提

### 1. 数据仓库必须是私有的

`Toylog123/tandian-data` 是 **PRIVATE**。
网页仓库 `Toylog123/tandian-biji` 是**公开的**——
GitHub Pages 免费版只支持公开仓库，私有仓库要 Pro / Team / Enterprise。

分开是因为：**代码可以公开，探店记录不能。**

### 2. token 只授权这一个仓库

用的是 **Fine-grained personal access token**。

建的时候在 **Repository access** 里：

- ✅ **Only select repositories** → 只勾 `tandian-data`
- ❌ **All repositories** —— 千万别选这个

选错的后果不是「数据会泄露」，而是**任何拿到这个 token 的人都能删掉你
GitHub 上全部的仓库**，包括你那些科研工程。Fine-grained 的界面默认
很容易点成 All repositories，点之前确认一遍。

权限勾 **Contents: Read and write** 就够了，别多给。

### 3. token 一个字都不进仓库

`js/config.js` 里只有：

```js
export const GH = {
  owner: 'Toylog123',
  repo:  'tandian-data',
  dataPath:  'data.json',
  photoPath: 'photos.json',
};
```

owner 和 repo 不是秘密。**token 由本人在自己设备上粘一次**，
存进那台设备的 localStorage（key: `lulu_gh_token`），填完立刻清空输入框。

公开仓库里根本没有 token 可泄露。

## 怎么连上

1. 打开网页 → ⚙️ **管理**
2. 在「云端同步」那栏找到输入框，粘贴 token
3. 点「连上」

顶部小圆点变成 `● 已同步` 就成了。
想立刻推一次，点「立即同步」；想断开，点「断开」。

**每台设备都要各自粘一次。** 手机 A 连上了，手机 B 还不知道这件事。

---

## 同步是怎么发生的

**往外推**（你在这台设备上改了东西）

- 改完就进待推送队列，但**不是每敲一下都提交**
- 合并成：**停手 90 秒**、或**切到后台**、或手动点「立即同步」
- 一个提交周期内改十次，只产生一次提交

为什么要合并：git 每次提交都存一份完整快照。
一天几百条提交，再小的仓库也会被撑坏。

**往里拉**（另一台设备改了东西）

三个时机：

- 打开页面时
- **切回前台时** ← 这是跨设备同步真正生效的地方
- 30 秒轮询兜底

拉到之后跟本地比，**内容一样就不写盘**，
所以不会打断你正在输入的东西。

**一个保护措施**：拉取之前先看本地有没有还没推上去的改动。
有的话**跳过这次拉取**。否则刚输入的东西会被云端的旧版本盖掉——
防抖窗口里最容易踩这个坑。

## 两个文件，不是一个

| 文件 | 装什么 |
|---|---|
| `data.json` | 店、探店记录（纯文本，UTF-8） |
| `photos.json` | 照片，按 id 索引 |

**为什么拆开**：git 每次提交都存一个完整快照。
照片是 base64，一张 30~45KB。如果混在 `data.json` 里，
改个店名就得提交几百 KB 的新 blob，几十次下来仓库直接膨胀。
拆开之后，改文字只提交几 KB，**图片没变就完全不动**。

---

## 两台设备同时改

GitHub 的写接口要求带上文件当前的 sha，对不上会返回 409。
遇到冲突时我们**重新读一次再覆盖**（后写覆盖，不做冲突合并）。

两个人同时在改同一家店的那一瞬间，有一方会被盖掉。
这个沙盒里几乎不会发生，但**它是已知限制，不是 bug**。

---

## 换了手机 / 重装浏览器怎么办

数据在 GitHub 仓库里，不在浏览器里。新设备：

1. 打开网页
2. ⚙️ 管理 → 粘同一个 token → 「连上」
3. 数据会从仓库拉下来

**反过来要注意**：localStorage 是绑域名的。
**别用无痕模式，别清站点数据**——清了等于删库
（虽然仓库里还有一份，但得重新粘 token 才拉得回来）。

## 想自己换一套仓库

改 `js/config.js` 一个文件就行：

```js
export const GH = {
  owner: '你的账号',
  repo:  '你的仓库名',      // 必须是私有
  dataPath:  'data.json',
  photoPath: 'photos.json',
};
```

仓库得先建好（可以是空的），内容第一次推送时自动生成。
建好之后按上面第 2 条给 token 授权。

没配 owner/repo 的话，**应用行为跟现在一模一样**，只是数据不共享。
