# 今天吃啥 · 家庭点菜板

给两个人用的：你在「管理」里录常点的外卖店，她打开网页点菜，
你在手机上看着清单去美团/饿了么下单。

**没有支付、没有配送、没有账号。** 只解决一件事：把「今天吃什么」这件事说清楚。

## 三个页面

| 页面 | 谁用 | 干什么 |
|---|---|---|
| 🏠 **店铺** | 她 | 按分类看你录的店 → 进店 → 点菜 → 填数量/谁点的/忌口 |
| 🧾 **清单** | 你 | 按店分组列出今天要点什么，**照着去下单**，下完点「去下单了」并写评价 |
| ⚙️ **管理** | 只有你 | 录店、录菜、改名改价、上下架 |

底部导航的 🧾 上有红色角标，是今天已点的份数。

## 评价怎么用

**写**
- 清单页每家店分组右下角有「⭐ 评价这家店」
- 店铺页底部也有「写评价」按钮，可以补录以前吃过的
- 弹层里：点星星 → 勾快捷标签（好吃/踩雷/别再点/有点咸…）→ 写一句话
- 快捷标签是为了**避雷用**的，下次一眼就知道哪家别点

**看**
- 店铺卡片上直接显示 `我给 2.8 ★ · 5 条`
- 店铺页头部显示均分和条数，底部是全部历史评价
- 点「去下单了」时，会提示你哪几家还没评价

**为什么是「我给」而不是店铺评分**
外卖平台的评分是所有人的平均值，对你个人没有参考价值。
这里存的是**你自己每次的真实感受**，
「拌面太咸」「卤蛋别点了」这种信息，下次点单时才真的用得上。

---

## 评价分两层：店铺 vs 菜品

这两层记的不是一回事：

| | 店铺评价 | 菜品描述 + 星级 |
|---|---|---|
| 记什么 | 整体印象：踩雷、送得快、别再点 | 具体这道菜：咸不咸、怎么点、值不值 |
| 入口 | 清单页「⭐ 评价这家店」/ 店铺页「写评价」 | 管理页菜品行 / 店铺页直接点星星 |
| 举例 | 「这店送得快」 | 「拌面咸得很，慎点」★2 |

**菜品星级可以直接点**——店铺页和管理页都能点，
点第 n 颗就是 n 分，**再点同一颗取消**。

「未评分」和「吃过但不好吃」是两回事：
前者是没吃过、不知道；后者是 1 星、别点了。别混。

**描述她会看到**，显示在菜名下面。所以要写成对她有用的信息：
「偏咸，备注少盐」比「很好吃」有用一百倍。

## 日常怎么用

**你这边（一次性）**
1. ⚙️ 管理 → ＋ 录店 → 填店名/平台/分类/备注（「微辣就好」这类记这里）
2. 点这家店 → ＋ 录菜 → 菜名、价格、**描述**、（有照片就传一张）
3. 吃过的菜顺手在管理页点星星打个分，或在店铺页直接点
4. 以后常点的东西就不用再录了

**她那边（每天）**
1. 打开链接 → 店铺 → 选店 → 点「加入」
2. 弹层里选几份、选是谁点的、写备注（不要辣 / 不要香菜）
3. 不用管最后一步，清单会自动更新

**你这边（每天）**
1. 🧾 清单 → 按店分好组了，一家一家照着点
2. 每家店底下有「去 XX 下单」按钮，点一下直接跳到美团/饿了么
3. 下完单点「去下单了」，提示你哪几家还没评价
4. 给每家写一句（星星 + 标签 + 文字），下次就有底
5. 不想点了就「全部清空」

## 菜品长什么样

一行就是：**左边一张照片，右边依次是菜名、评价、描述。**

![菜品行布局](docs/dish-row.jpg)

- **没有图标**。以前会用 emoji 占位，但 emoji 看着像某道菜、点进去不是那家的菜，
  认错了比没有更糟，所以宁可不画——没照片就是一块浅色占位。
- 照片会自动压到最长边 400px 的 JPEG，一张 30~45KB，存一百多张都没问题。
- 菜名和价格同一行，价格靠右；下面是星级，再下面是描述。

**传照片**：⚙️ 管理 → 对应那道菜的 📷 → 选图。
「＋ 录菜」时也可以顺手传，传完还能 ✕ 换掉。
管理页底下会显示「已用 XX MB，还够放大约 N 张图」。

## 怎么跳到美团下单

点「去美团下单」时按这个顺序走：

1. 先用 scheme 唤起 App（手机上装了美团就直接跳进 App）
2. 1.6 秒后本页还在前台 → 说明没装 App，回退到网页版

**想一步直达那一家店**，在 ⚙️ 管理 → 「店铺设置」→ 店铺链接里，
从美团 App 的店铺页「分享 → 复制链接」把地址粘进来。
粘了链接就**直接用你的链接**，不再做 App 唤起。

> 查证记录：美团外卖 H5 是 `https://waimai.meituan.com/`。
> 网上到处流传的 `https://www.meituan.com/waimai/` 是错的，实测直接返回 Not Found。
> 饿了么 H5 `https://h5.ele.me/` 能找店但**不能下单结算**，所以饿了么主要靠 App 唤起。

## 数据在哪

**默认存在浏览器的 localStorage 里**（key: `lulu_family_menu_v1`）。

没配后端时：**换浏览器、换设备、清缓存，数据就没了。** 两个人各看各的。

配了后端之后：数据会额外同步一份到云端，两台手机看到的是同一份。
做法见 **[docs/接入后端.md](docs/接入后端.md)**——需要一个免费的 Supabase 项目，
没有服务器、没有域名、没有构建。**没配的话应用行为跟现在完全一样。**

判断当前是哪种：⚙️ 管理页标题那里有个小圆点，
`仅本机` / `同步中…` / `已同步` / `云端没连上，先存本地`。

数据层是隔离好的：所有读写都走 `js/store.js`，
云端同步在 `js/backend.js`，两者互不影响。

## 文件结构

```
lulu-family-menu/
├─ index.html          页面骨架 + 底部导航 + 隐藏的选图 input
├─ css/style.css       全部样式（噜噜芒果黄 #FFD100）
├─ js/store.js         数据层 + 示例数据   ← 想改数据结构动这个
├─ js/app.js           路由 + 四个页面 + 弹层
├─ js/img.js           图片压缩（canvas → 400px JPEG）
├─ js/backend.js       云端同步（没配后端就是空操作）
├─ js/config.js        填 Supabase 的 url 和 key   ← 接后端只动这个
├─ docs/
│   ├─ 接入后端.md     Supabase 建表 SQL + 接入步骤
│   └─ dish-row.jpg    菜品行布局示意
└─ assets/             噜噜形象图（4 张 webp）
```

路由用 hash（`#/shop/s1`），丢到 GitHub Pages 这种没有 rewrite 规则的
静态托管上也能直接跑。

## 已知的取舍

- **默认数据不共享**，各人浏览器各存一份（接后端的方法见 `docs/接入后端.md`）
- **后写覆盖**：两个人同时改不同东西时，后写的会盖掉先写的，没做冲突合并
- **没有推送**，她点完你不会收到通知，得自己看一眼清单
- **没有历史订单筛选**，只留最近 5 条
- 「谁点的」是写死的两个名字（我 / 她），要改在 `store.js` 的 `SEED.people`
- 图片存的是 dataURL，占 localStorage（浏览器一般给 5MB）；接后端后应改成存 URL
