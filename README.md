# 探店笔记

自己的探店档案库。**每家店做永久记录**，下次吃饭前先翻一翻，
一眼躲开上次踩雷的，直接奔上次强烈推荐的。

**没有支付、没有配送、没有下单、没有账号。**
只解决一件事：「这家到底行不行，下次还去不去」——记下来，别靠脑子。

## 两个页面

| 页面 | 干什么 |
|---|---|
| 💛 **档案** | 按评分分四组的店列表 + 店档案页。吃饭前翻这个 |
| ⚙️ **管理** | 录店、写一句话总结、改设置、连云端 |

首页按**均分**排成四组，不是按字母也不是按分类：

| 分组 | 阈值 | 长什么样 |
|---|---|---|
| 💛 强烈推荐 | ≥ 4.5 ★ | 卡片左侧金色竖条 |
| 🙂 还可以 | ≥ 3.5 ★ | 绿色竖条 |
| 😐 一般 | ≥ 2.5 ★ | 灰蓝竖条 |
| ⛔ 别再去 | < 2.5 ★ | 浅红底 + 红标题，**最扎眼的一组** |
| ❓ 还没记过 | — | 灰色。「没吃过」和「吃过不好吃」是两回事，别混 |

阈值不是随手定的：5 星「很好吃」、4 星「还不错」、3 星「一般般」、
2 星「不太行」、1 星「难以下咽」。均分 ≥4.5 值得专程去，<2.5 就别了。

**「还没记过」单独一组**，因为它跟差评语义完全不同。
把没吃过混进「别再去」是误导。

## 探店记录：去一次记一条

这是整个应用的中心。**不覆盖历史**——每次去都追加一条，
所以能看到「这家我吃过三次，第二次咸了第三次好了」。

**记**
- 店页上的「记一次」按钮，吃饭后随手点
- 弹层里：**日期 + 人均 + 星级 + 照片 + 一句话**
  - 日期默认今天，可以往前改 —— **补录上个月吃过的也录得进去**
  - 人均可留空。留空是「没记」，填 0 是「真的是 0 元」，**两件事分开存**
  - 星级默认填上次打的分（大多数时候不用改）
  - 照片最多 **9 张**，自动压到 400px 再存
  - 快捷标签（好吃/踩雷/别再点/有点咸…）预勾上次的，点一下取消

**看**
- 店页头部一颗档位胶囊：`💛 强烈推荐 · 5 ★`，旁边是人均均价
- 下面是时间线，倒序排列，每条带星级图、日期、人均、标签、照片、一句话
- 存档库页卡片直接显示均分和去过几次

### 四种排序

记录多了光看时间线不够用，店页给了一条排序条：

| 排序 | 用途 |
|---|---|
| 最近去 | 默认。上次去的是什么时候 |
| 星数高 | 把踩雷的沉到底下 |
| 人均低→高 | 找便宜的 |
| 人均高→低 | 找贵的 |

**没填价格的永远排最后**，升序降序都一样。
最没信息的一行不该占最好的位置——降序要是把空的顶到最前面，
等于在推荐一条「人均未知」的记录。

### 日期和录入时间是两回事

- `date` 是**去的那天**，可以改，用来补录历史
- `createdAt` 是**录入的那天**，不能改，用来排时间线顺序

### 为什么存的是「我给的星」而不是平台评分

外卖平台的评分是所有人的平均值，对你个人没有参考价值。
这里记的是**你自己每次的真实感受**——
「拌面太咸」「这家咸，放一起就对了」这种信息，下次决定去不去才真的用得上。

## 一句话总结：下次靠这句想起来

每家店可以写**一句话总结**，跟单次记录里的「一句话」不是一回事：

| | 一句话总结 `shop.summary` | 记录里的话 `visit.text` |
|---|---|---|
| 挂在哪 | 店的档案卡片上，一直显示 | 只在那一行记录里 |
| 记什么 | 跨所有次数的**总印象** | 这次吃的**具体情况** |
| 什么时候写 | 吃到第 3 次才写得出来 | 每次随手写 |

一句「黄焖鸡里的标杆。汤足肉嫩，唯一的毛病是咸，备注少盐就完美」，
比看十条「还不错」有用得多。

写的地方：⚙️ 管理 → 选那家店 → 「一句话总结」，输入即自动保存。
首页卡片上会直接显示，写太长自动省略成一行。

## 星级配图

每一档星级对应**好几张**噜噜动态表情，看哪张是随机的。
店卡片和每条记录前面都放对应星级的那张。

**随的是「这一条记录」，不是每次渲染。** 同一条记录永远是同一张图——
要是每次刷新都重摇一遍，页面一滚动图就跳，同一条记录前后两张脸对不上，
看着像坏了。用记录 id 散列代替真随机，既稳又不用往数据里多存字段。

| 星级 | 张数 |
|---|---|
| ⭐ 1 | 4 |
| ⭐⭐ 2 | 3 |
| ⭐⭐⭐ 3 | 2 |
| ⭐⭐⭐⭐ 4 | 3 |
| ⭐⭐⭐⭐⭐ 5 | 2 |

**该放照片的位置一律放真图，没图给中性色虚线占位块，绝不退回 emoji 图标**
——emoji 看着像另一个表情、另一个东西，认错了比没有更糟。

> 补图只要两步：把文件丢进 `assets/rating/`，然后往 `js/app.js` 的
> `RATING_ART` 对应数组里加一行文件名。

## 数据在哪

**默认存在浏览器的 localStorage 里**（key: `lulu_family_menu_v1`）。

没连云端时：**换浏览器、换设备、清站点数据，数据就没了。**

连上之后：数据会同步到一个**私有 GitHub 仓库**（`Toylog123/tandian-data`），
你两台手机看到的是同一份。谁记了一条，另一台切回前台就能看到。
做法见 **[docs/同步到GitHub.md](docs/同步到GitHub.md)**。

判断当前是哪种：⚙️ 管理页标题那里有个小圆点，
`仅本机` / `同步中…` / `已同步` / `没连云端` / `token 无效`。

### token 不进仓库

**网页和仓库都是公开的，token 写进代码等于没设防。**
每台设备自己粘一次，存在那台设备的 localStorage 里（key: `lulu_gh_token`）。
用的是 Fine-grained PAT，**只授权 `tandian-data` 这一个私有仓库**。

### 数据结构

```js
shop  = { id, name, category, note, summary, createdAt }
visit = { id, shopId, date:'YYYY-MM-DD',   // date = 去过的那天，可改
          rating:1-5, price:number|null,   // null = 没填；0 = 真的是 0 元
          text, tags[], images[],         // 一次去一条，只追加不覆盖
          createdAt }                     // 录入的那天，排时间线用
```

> ⚠️ **加字段必须在 `js/store.js` 的 `migrate()` 里补一行。**
> 老数据是从旧版存下来的，没有新加的键，直接读会拿到 undefined，页面一渲染就白屏。

## 文件结构

```
lulu-family-menu/
├─ index.html          页面骨架 + 底部导航 + 隐藏的选图 input
├─ css/style.css       全部样式（噜噜芒果黄 #FFD100 + 四档位色）
├─ js/store.js         数据层 + 评分档位 TIERS + migrate   ← 改数据结构动这个
├─ js/app.js           路由 + 两个页面 + 弹层 + 星级配图
├─ js/img.js           图片压缩（canvas → 400px JPEG）
├─ js/ghstore.js       GitHub Contents API 读写（云端存储）
├─ js/config.js        仓库地址 owner/repo/path，**没有 token**
├─ docs/
│   └─ 同步到GitHub.md 怎么把仓库接成两台手机共用的存储
└─ assets/
    ├─ lulu-*.webp     场景图（4 张，AI 仿制）
    └─ rating/         星级配图（14 张 GIF，按星级分文件）
```

路由用 hash（`#/shop/s1`），丢到 GitHub Pages 这种没有 rewrite 规则的
静态托管上也能直接跑。

## 已知的取舍

- **后写覆盖**：两台设备同时改，后写的盖掉先写的，没做冲突合并
- **90 秒合并推送**：打字停顿不产生 commit，切后台立刻推
- **没有分享/导出功能**，档案只能自己看
- **照片存的是 dataURL**，会占空间；管理页底部有剩余容量提示
- **App scheme 唤起已随「跳去下单」一起移除**
- **图片压缩到 400px**，想存原图得改 `js/img.js` 的 `MAX_EDGE`
